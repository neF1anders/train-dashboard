# Сириус · Разбор

Локальный MVP для анализа архивных поездок трамваев. Два экрана: выбор записи и рабочее окно с временем, картой, реконструкцией и проверяемым разбором.

## Запуск

После клонирования подготовьте данные по инструкции ниже. В Windows с Python 3.11+ из корня проекта:

```powershell
.\scripts\start-local.ps1
```

Скрипт использует локальный runtime Codex, если он установлен, иначе `python` из PATH. Можно явно указать интерпретатор: `.\scripts\start-local.ps1 -PythonExecutable 'C:\Python311\python.exe'`.

Адрес: **http://localhost:5173/**. Процесс работает в фоне, привязан только к `127.0.0.1`. Журналы: `tmp/localhost.stdout.log`, `tmp/localhost.stderr.log`.

Без фонового запуска, на Python 3.11+:

```powershell
python -m app.server --port 5173
```

Остановить такой запуск можно `Ctrl+C`. Сторонние Python- и npm-пакеты для приложения не нужны. Интерфейс, городская геометрия и API работают локально, без CDN и внешних сервисов.

## Данные

В рабочем локальном окружении полный импорт выполнен: 122 исходных файла, 69 различных источников после группировки файлов, **1 174 424 уникальные записи**, включая **647 576 JSON**. Остальные — CSV. Все 6 вагонов, фактические даты 14 сентября — 6 октября 2026. Подробности покрытия: `analysis/coverage-summary.json`; 470,5 часа — наблюдения с остановками и исключением разрывов более 30 секунд.

**В Git не входят исходные логи, архивы, видео, SQLite, история просмотров и подробные выгрузки аудита.** Включены код, спецификации, сводка покрытия, перечень файлов с хешами и публичная карта OSM. После клонирования база создаётся локально:

1. Скачайте `hakathon_new_data.rar` и `hakathon.rar` из [папки материалов кейса](https://drive.google.com/drive/folders/1QDDQuGqczPKVIC_0D_1kbjPmbEZvGOnN).
2. Распакуйте первый архив в `materials/extracted/new/`, второй — в `materials/extracted/original/`, сохранив внутренние имена каталогов. Ожидаемые пути и SHA-256 указаны в `analysis/file-inventory.json`. Например, первый архив должен дать `materials/extracted/new/hakathon/3139/3139_14_09/1_move_detailed_3139.csv`.
3. Выполните `python -m app.ingest`, затем запустите сервер. Для распакованных материалов и базы потребуется примерно 10 ГБ свободного места. Без импорта каталог поездок пуст.

Первичная подготовка или повторный импорт:

```powershell
python -m app.ingest
```

Импорт потоковый, возобновляемый. Завершённые источники пропускаются, точные записи имеют уникальный SHA-256. Исходники не изменяются. SQLite находится в `data/sirius.sqlite3` (около 1,5 ГБ). Каталог, эпизоды, история и результаты анализа хранятся на сервере. Прогресс: `data/import-progress.json`.

События группируются по вагону, дню, маршруту, типу и цели с максимальным промежутком 8 секунд. Это навигационные группы записей, не подтверждённые отдельные аварии или инциденты. Правило открыто в `app/ingest.py`.

CSV-время без зоны принято за UTC+3. Для движения выбирается JSON на всём непрерывном участке его покрытия; CSV заполняет периоды вне этих участков. Переключение между двумя источниками каждую секунду исключено. Слишком близкие по времени точки прореживаются только для обзорного трека; оригинальные записи обоих источников остаются в доказательствах. Редкие коды CSV выводятся с указанием источника, их связь с кодами JSON не выдумывается.

## Что работает

- Зависимые фильтры вагона, реальной даты и маршрута, включая периоды только с CSV.
- История просмотров и сохранённых анализов; восстановление интервала, курсора, вида и карты после возврата или перезагрузки.
- Общая шкала и приближение выбранного интервала, события, разрывы, точные границы, перемотка, шаг по записи, 0,25×–4×. Панель прокручивается вместе со страницей. Наведение даёт предпросмотр сцены и сигналов; уход со шкалы возвращает зафиксированный момент, нажатие закрепляет новый.
- Выездная карта справа, доступная также по плавающей кнопке. На фоне улиц отображаются путь выбранного вагона на одном маршруте и его события. Общая трамвайная сеть скрыта. Близкие события объединяются в группы с выбором конкретного времени; доступны фильтры типов, список событий, масштаб и выбор повторного проезда через место.
- 2D/3D из общей временной модели: плавная геометрия GPS, типовой вагон, параллельные рельсы, постоянное направление камеры, устойчивый поворот корпуса и корректное отображение реверса. Одометрия остаётся проверяемой телеметрией; смена дискретного снимка больше не сдвигает вагон.
- На разрыве достоверной траектории воспроизведение останавливается. Последнее известное положение остаётся на экране с пояснением и кнопкой перехода к следующему участку. Карта и график кешируют неподвижные слои, а подробная телеметрия подгружается блоками.
- Расширенные снимки распознавания, их собственное время, объекты и светофоры; схема локальной геометрии включается отдельно и помечает неподтверждённые оси/масштаб. Потерянные объекты показаны пунктиром; будущие снимки не подставляются.
- Серверный разбор выбранного интервала, подтверждающие записи, ограничения, вопросы о вмешательстве/управлении/торможении/скорости, сохранение и JSON-экспорт.
- Исходная запись, файл, номер блока или CSV-строки, JSON-путь и хеш записи.
- Светлая/тёмная тема, адаптивная вёрстка. Space — воспроизведение, стрелки — шаг, когда фокус не в поле или кнопке.

## Ограничения первой версии

Разбор и вопросы работают **по явным правилам**, не через подключённую языковую модель. Неизвестные вопросы получают честное пояснение области поддержки. Это не произвольный ИИ-чат. Настоящая LLM-интеграция требует выбора модели и способа доступа.

3D-модель типовая. Геометрия рельсов в сцене следует треку, а не гарантированно установленной колее. Ближайшая улица/путь OSM — кандидат; полная привязка по связности сети ещё не реализована. Положение объектов неизвестно в большинстве записей; там объекты не добавляются. Система координат `pose` требует подтверждения у организаторов. Нет привязанного видео и управления реальным движением.

Сглаживание координат, отбрасывание одиночных выбросов и ограничение резкости поворота относятся только к визуализации. Они не меняют исходные записи, временные метки, анализ или его доказательства. Непрерывная кривая отображения не подтверждает точную геометрию реального пути. На уровне корпуса трамвай может менять направление движения без разворота модели на месте.

Основная единица выбора — вагон/дата/маршрут, разрывы видны внутри записи. Автоматическое восстановление рейсов через полночь и многопользовательские роли в эту локальную версию не входят. История общая для данного локального приложения.

Хранилище и интерфейс MVP реализованы на стандартном Python + SQLite и модульном JavaScript/Canvas. Это замена предложенного в раннем плане стека ради запуска без установки зависимостей; функциональные компоненты отделены от API.

## Проверки

```powershell
python -m unittest discover -s tests -p 'test_*.py' -v
node tests/motion.cjs
```

Браузерный сценарий `tests/browser.cjs` использует установленный Chrome и bundled Playwright. Он проверяет выбор архива, известное срабатывание, ссылки на доказательства, 2D/3D, карту, устаревший анализ, восстановление после перезагрузки, CSV-периоды и ширины 320–1440 px. Скриншоты и результаты сохраняются в `tmp`.

`tests/reconstruction.cjs` проверяет переход к собственному времени снимка, переключение проекций и независимость положения вагона от обновления дискретной одометрии. `tests/ui-regressions.cjs` проверяет прокрутку, предпросмотр и фиксацию времени, выездную карту, клики по группам событий, переход через реальный разрыв, отдельный маршрут на карте и ширины 320–1440 px. Он также измеряет время отрисовки сцены и число запросов при воспроизведении.

Проверены 10 Python-тестов, проверки геометрии движения и три браузерных сценария. В локальном прогоне 4× отрисовка сцены заняла около 2,2 мс на 95-м процентиле; это результат данного компьютера и эпизода, не гарантия для других устройств. Дополнительно прогнаны крупнейшие записи каждого из шести вагонов: нет провалов положения внутри принятых непрерывных участков, резкие развороты корпуса устранены. Подробные измерения сохраняются локально в `tmp`.

## Структура

- `app/ingest.py` — импорт и индексация.
- `app/server.py` — локальный HTTP/API.
- `app/analysis.py` — проверяемые правила и ответы.
- `app/geo.py` — локальное сопоставление с OSM.
- `web/` — приложение без внешних ресурсов.
- `web/motion.js` — единая геометрия и положение вагона по времени.
- `web/timeline.js` — кешированная шкала с предпросмотром и переходом.
- `materials/` — неизменённые материалы кейса.
- `docs/MVP_SPEC.md` — согласованная продуктовая спецификация.

Геометрия города: © OpenStreetMap contributors, [ODbL](https://www.openstreetmap.org/copyright). Файл `analysis/osm-spb-public.json` содержит публичные выбранные слои Санкт-Петербурга от 08.10.2026, источник — [Overpass VK Maps](https://maps.mail.ru/osm/tools/overpass/api/interpreter). Подробные локальные отчёты, на которые ссылается продуктовая спецификация, остаются в рабочем окружении и не публикуются в Git.
